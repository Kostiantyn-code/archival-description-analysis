# Офлайн-карти й реєстр населених пунктів

Звичайний запуск аналізу, зокрема через `run.bat`, перевіряє останній
опублікований GitHub Release. Перший запуск із доступом до мережі може
завантажити підкладку й реєстр. Програма перевіряє розмір і SHA-256
з метаданих GitHub та зберігає перевірені файли в `map-data/`.
Перевірка відбувається щонайбільше раз на добу.

Якщо перевірка або завантаження переривається, аналіз використовує
раніше збережені дані. На чистому встановленні доступні базова
підкладка й словник топонімів із репозиторію. Leaflet 1.9.4 та його
ліцензію програма додає до папки результатів. Збережіть її цілком для
офлайн-перегляду або передавання. [Джерела підкладки](methodology.md#map-attribution)
· [Пакет Leaflet 1.9.4](https://registry.npmjs.org/leaflet/-/leaflet-1.9.4.tgz)

Для запуску в ізольованому середовищі змініть параметр у `config/analysis.yaml`.
Перш ніж аналізувати XLSX без мережі, встановіть залежності Python.

```yaml
maps:
  auto_update: false
```

Готовий або власноруч [зібраний реєстр](city_register.md) можна підключити,
поклавши `registry.sqlite` у `map-data/`. Цей файл має пріоритет над
завантаженою копією. За наявності реєстру таблиця
`geography_registry_matches.csv` містить можливі відповідники для
нерозпізнаних топонімів. Позначки на карті формуються за перевіреним
словником топонімів проєкту.

## Публікація даних у GitHub Releases

Додайте файли до останнього опублікованого релізу як вкладення з точними назвами.

| Файл | Вміст |
|---|---|
| `europe-basemap.geojson` | Підкладка GeoJSON типу `FeatureCollection`, підготовлена за схемою [базової карти](../maps/europe-basemap.geojson). |
| `reiestr-naselenykh-punktiv.zip` | ZIP із `registry.sqlite` у корені. До пакета додайте маніфест джерел та атрибуцію GeoNames. |

Завантажувач використовує SHA-256 вкладення з GitHub Releases API. Кожне
вкладення оновлюється окремо. [Документація GitHub Releases](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)
