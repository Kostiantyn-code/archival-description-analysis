# Аналіз архівних описів

Відтворюваний Python-конвеєр для перевірки, нормалізації, багатозначної
тематичної класифікації та кількісного аналізу архівних описів.

Поточна версія програми — `0.10`; версія класифікаційних словників —
`0.8-draft`.

## Призначення

Проєкт опрацьовує всі книги `.xlsx` у папці `input/`, не змінюючи їх.
Кожна книга є окремою дослідницькою добіркою, а кожний її аркуш — описом.
Архів, фонд та опис читаються з перших трьох рядків аркуша. Для кожної книги
формуються власні перевірки даних, статистичні таблиці, тематичні вибірки,
графіки та звіти. Кілька фондів в одній книзі отримують окремі звіти
й спільний зріз `combined` у межах цієї книги.

## Можливості

- перевірка структури XLSX, номерів справ, дат, кількості аркушів і дублікатів;
- окрема категорія «Особові справи та персональний облік»: врахування явного
  заголовка розділу для справ, названих лише прізвищами, та поіменних списків;
- розпізнавання справ, вибулих записів, заголовків років, групових та інших
  службових рядків;
- окрема обробка українських і російських заголовків без їх перекладу;
- багатозначна тематична класифікація: одна справа може належати до кількох
  категорій;
- розмежування предметної теми та контекстної згадки особи, посади чи установи;
- статистика за окремими фондами та об’єднаним корпусом кожної книги;
- розподіли за десятиліттями, роками, категоріями, описами та станом класифікації;
- тематичні XLSX/CSV-вибірки зі збереженням структури первинної книги;
- графіки PNG/SVG і машинозчитувані службові таблиці;
- журнал помилок, аналітичний звіт і маніфест запуску з контрольними сумами.

## Встановлення і запуск

Потрібен Python 3.12 або новіший. Створіть папку `input/` поруч із
`fond_analysis.py` і покладіть у неї одну або кілька книг `.xlsx`.

### Windows

Запустіть `run.bat`. Під час першого запуску він:

1. перевірить наявність Python та книг `.xlsx` у `input/`;
2. створить локальне середовище `.venv`;
3. встановить залежності з `requirements.txt`;
4. запустить аналіз.

Наступні запуски використовують уже створене середовище.

### Командний рядок — Windows

```text
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python fond_analysis.py
```

### Командний рядок — Linux і macOS

```text
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python fond_analysis.py
```

Команди можна виконувати в будь-якому терміналі або середовищі розробки.
Робочий каталог не впливає на пошук файлів: шляхи визначаються від
розташування скрипта.

## Вхідні дані

Вимоги до структури описано в [input/README.md](input/README.md): на кожному
аркуші A1:B3 містять `Архів`, `Фонд`, `Опис`; четвертий рядок — шапка колонок
A–E, записи — з п’ятого рядка. Назви аркушів довільні. Мова українських
або російських заголовків визначається за вибіркою заголовків аркуша;
евристичний результат можна перевірити в маніфесті книги. Порожні дати або
число аркушів не приховуються й потрапляють до контролю якості.

Первинні книги не редагуються. Кожен запуск створює нову папку результатів;
зіпсована книга позначається `failed` у загальному `run_summary.csv`,
а обробка решти продовжується.

## Результати

```text
outputs/
└── YYYYMMDD_HHMMSS_microseconds/
    ├── run_summary.csv
    └── назва_книги/
        ├── thematic_exports/
        ├── tables/
        │   ├── fond_230_…/
        │   ├── fond_356_…/
        │   ├── combined/
        │   ├── classification_index.csv
        │   └── source_summary.csv
        ├── figures/
        │   ├── fond_230_…/
        │   ├── fond_356_…/
        │   └── combined/
        ├── reports/
        │   ├── fond_230_…/
        │   ├── fond_356_…/
        │   └── combined/
        └── run_manifest.json
```

Основні матеріали:

| Результат | Призначення |
|---|---|
| `classification_index.csv` | класифікація кожної справи, бали, ознаки та тематичний розділ опису |
| `description_summary.csv` | контрольні підсумки за архівними описами |
| `cases_by_year.csv` | річний розподіл справ в окремих колонках за описами |
| `cases_by_year.png/.svg` | окремі хронологічні ряди за описами книги |
| `unclassified_cases.csv` | справи без визначеної предметної категорії |
| `needs_review.csv` | неоднозначні випадки для експертного перегляду |
| `thematic_exports/*.xlsx` | похідні переліки справ за тематикою |
| `analysis_report.md` | текстовий підсумок запуску |
| `error.log` | помилки й попередження щодо вхідних даних |
| `run_manifest.json` | версії, параметри, джерела й контрольні суми файлів книги |
| `run_summary.csv` | загальний стан обробки кожної книги, кількість аркушів і справ |

Каталоги `fond_*` містять звіти за архівними фондами. `combined` зводить
усі аркуші **однієї книги**; це дослідницький корпус, а не облікова кількість
справ одного архівного фонду.

## Конфігурація

| Файл | Призначення |
|---|---|
| `config/analysis.yaml` | вхідна папка, папка результатів, хронологічні межі та експорт |
| `config/categories.yaml` | категорії, макроблоки, статус увімкнення та шляхи словників |
| `dictionaries/` | українські й російські правила тематичної класифікації |

Правила «право на проживання» та
«портові збори» уточнюють уже наявні теми. Для записів під окремим
заголовком «Особові справи ув’язнених» додаються тип документації та
«Право, суд і поліція»; літера й рік усередині розділу його не переривають.
Ім’я без такого розділу саме по собі не визначає тему.

Категорії керуються конфігурацією. Якщо категорію вимкнути через
`enabled: false`, вона не завантажуватиметься і не створюватиме вихідного
файла. Додавання нової категорії з відповідними словниками автоматично
поширюється на класифікацію, статистику, графіки та тематичний експорт.

## Інтерпретація результатів

- Класифікація є багатозначною, тому сума категорій може перевищувати
  кількість справ і 100%.
- Бали відображають вагу словникових правил, а не статистичну ймовірність.
- `context_only` означає, що в заголовку знайдено лише контекстну згадку без
  достатніх ознак предметної теми.
- `unclassified` не означає відсутності історичного змісту: це заголовки, для
  яких наявні словники не дали достатньої підстави для класифікації.
- Тематичні XLSX-файли є похідними дослідницькими вибірками, а не новими
  архівними описами.
- Автоматичні результати потребують експертної перевірки, насамперед за
  файлами `needs_review.csv` та `unclassified_cases.csv`.
