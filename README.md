# Archival Description Analysis

Reproducible Python tools for quantitative and thematic analysis of archival descriptions.

[Українською](#українською) · [English](#english)

> **Статус проєкту:** робоча версія `0.4-draft`. Репозиторій містить придатний
> до запуску Python-скрипт, класифікаційні словники та документацію методики.
> Повний масив архівних описів не публікується.

## Українською

### Про проєкт

**Archival Description Analysis** — дослідницький програмний проєкт для
відтворюваного кількісного та тематичного аналізу архівних описів засобами
Python.

Поточна реалізація створена для аналізу описів фонду 230 «Канцелярія
Миколаївського військового губернатора» Державного архіву Миколаївської
області. Надалі цей самий підхід планується застосувати до фонду 356
Центрального державного історичного архіву України, м. Київ.

Одиницею аналізу є запис архівного опису: номер справи, заголовок, крайні дати,
кількість аркушів і примітки. Програма аналізує метадані та заголовки справ, а
не повні тексти документів.

### Поточна реалізація

Скрипт `fond_analysis.py`:

- читає аркуші `Опис 1`–`Опис 4` із файла `input.xlsx`;
- розпізнає справи, заголовки років, записи про архівний опис і службові
  позначки `ВИБУЛА`, `ВИБУЛИ`, `ВИБУЛО`, зокрема надруковані з міжлітерними
  пробілами;
- перевіряє структуру таблиці, дати, дублікати, пропуски та нетипові значення;
- не включає вибулі й структурні записи до змістового аналізу;
- виконує багатозначну тематичну класифікацію за відкритими YAML-словниками;
- формує службові CSV, `error.log`, аналітичний звіт і графіки PNG/SVG;
- показує прогрес тривалої тематичної класифікації.

Версію словників `0.4-draft` додатково перевірено за 1 086 рядками, які
залишилися без теми після запуску `0.3-draft`. Виявлено 23 службові позначки
вибуття з міжлітерними пробілами. Із 1 063 змістовних заголовків нові
високоточні правила класифікують 429, а 634 свідомо залишають без категорії.
Очікуване покриття повного корпусу — близько 94,71%; остаточні значення слід
зафіксувати повторним запуском на актуальному `input.xlsx`.

### Важливе застереження щодо кількості справ

Попередній запуск помилково включив до аналізу 23 службові рядки з позначками
`В И Б У Л А`, `В И Б У Л И` або `В И Б У Л О`. Після їх відокремлення
розрахункова кількість заголовків справ становить **11 980**. Вона відрізняється
на 8 позицій від офіційної кількості **11 988 справ**, тому ця розбіжність ще
потребує окремої звірки структури описів і нумерації. Число 11 980 не слід
подавати як остаточний обсяг фонду без такого пояснення.

### Тематична модель

Класифікація є багатозначною: одна справа може належати до кількох категорій.

| Макроблок | Категорії |
|---|---|
| Політичне й адміністративне життя | політика і політичний нагляд; державне та місцеве управління; право, суд і поліція; військові та військово-морські справи |
| Соціально-економічне життя | економіка, фінанси й господарство; населення і соціальна сфера; охорона здоров’я і санітарія; міське господарство та інфраструктура |
| Культурне життя | освіта; культура, друк і громадське життя; релігія і конфесійне життя |

Словники створено з урахуванням структури УДК, історичної лексики XIX століття
та частотного аналізу заголовків фонду. УДК використовується як
класифікаційний орієнтир, а не як автоматична заміна архівного змістового
аналізу.

### Запуск у PyCharm Community Edition

1. Розмістіть у одній папці:

   - `fond_analysis.py`;
   - `input.xlsx`;
   - папку `dictionaries`.

2. Установіть обов’язкові бібліотеки:

   ```powershell
   python -m pip install openpyxl pyyaml
   ```

3. Для створення графіків додатково встановіть:

   ```powershell
   python -m pip install matplotlib
   ```

4. Запустіть `fond_analysis.py` у PyCharm.

Програма бере `input.xlsx` із папки, де розміщений сам скрипт.

### Результати запуску

```text
reports/
├── error.log
└── analysis_report.md

figures/
├── *.png

work/

├── unclassified_cases.csv
```

Папка `work` містить службові таблиці для перевірки й повторного аналізу.
Основними користувацькими результатами є матеріали з `figures` та `reports`.

### Методологічні принципи

1. **Розмежування одиниць підрахунку.** Кількість уживань терміна не
   ототожнюється з кількістю справ.
2. **Реальна хронологія.** Динаміка визначається за крайніми датами справ, а не
   за умовним поділом суцільного тексту.
3. **Прозора класифікація.** Категорії, ключові слова, ваги, контекстні правила
   й винятки зберігаються у відкритих YAML-файлах.
4. **Збереження першоджерела.** Нормалізований текст не замінює оригінальний
   заголовок справи.
5. **Обережна інтерпретація.** Частотність заголовків характеризує структуру
   архівного опису, але сама по собі не вимірює інтенсивність історичних
   процесів.
6. **Відмова від примусової класифікації.** Недостатньо інформативний заголовок
   може залишатися без тематичної категорії.

## English

### About

**Archival Description Analysis** is a research software project for
reproducible quantitative and thematic analysis of archival finding-aid
records with Python.

The current `0.4-draft` implementation contains an executable analysis script,
transparent YAML classification dictionaries, and methodological
documentation. Its initial case study concerns Fond 230, Office of the
Mykolaiv Military Governor, preserved at the State Archives of Mykolaiv Region.

The software validates XLSX records, distinguishes substantive and service
entries, performs multi-label thematic classification, and produces CSV
tables, reports, and PNG/SVG figures. Full archival datasets are not included
in the repository.

### Research status

Projected dictionary coverage is approximately 94.71%, pending a full rerun
on the current workbook. A discrepancy between
the calculated 11,980 substantive titles and the official figure of 11,988
files remains under review and is documented transparently rather than being
silently reconciled.
